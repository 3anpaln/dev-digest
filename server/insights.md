# API insights

- **2026-11-20** A successful readiness probe confirms database connectivity. Workspace routes also need the user and workspace created by the seed. [Health routes](src/app.ts#L118) · [Local auth](src/adapters/auth/local.ts#L22)
- **2026-11-20** When a Git diff is unavailable, the review can use patches persisted during PR import. For an unexpected diff, check which source supplied it and which head SHA the PR row records. [Diff loader](src/modules/reviews/diff-loader.ts#L29) · [PR import](src/modules/pulls/routes.ts#L203)
- **2026-11-20** When adding structured fields to saved run logs, verify a completed trace and a failed or cancelled trace after reload. The success path uses [RunLogger.logFor](https://github.com/3anpaln/dev-digest/blob/044387312e407502bb6efc83687e572813f77c30/server/src/platform/run-logger.ts#L94), while the [executor](https://github.com/3anpaln/dev-digest/blob/044387312e407502bb6efc83687e572813f77c30/server/src/modules/reviews/run-executor.ts#L430) maps the event buffer separately on failure and cancellation. A field visible over SSE can disappear in either saved trace.
- **2026-11-20** follow-up to “When adding structured fields to saved run logs”. All terminal paths now use [savedLog](src/platform/run-logger.ts#L36). For cancellation coverage, pause the first map request, cancel through the API, then release its billed response. The saved trace must include that charge and the next chunk must never start. The [lifecycle test](test/reviews.it.test.ts#L339) caught stream closure clearing the cancellation flag before the executor reached its checkpoint.
- **2026-11-20** When a PR card appears cheaper than a multi-agent review, compare the selected run ID and its saved attempt charges with the other agents started by the same action. “Run all” creates one run per agent, and the card reports only the latest agent. [Run creation](src/modules/reviews/service.ts#L120) · [Card cost selection](https://github.com/3anpaln/dev-digest/blob/0db97afab43d0f0de9a18ce527e2cded55f7d9e9/server/src/modules/pulls/latest-run.ts#L34)
- **2026-11-21** When selecting the latest review cost for a PR, filter agent runs by workspace before ranking them. The run and PR have separate workspace links, so the database can accept a foreign-workspace run that points at a local PR. A trace inherits its workspace through its run ID. In regression tests, give the newer foreign run a priced trace so dropping the workspace filter exposes the wrong cost. [Run selection](https://github.com/3anpaln/dev-digest/blob/c3a749db8ca0fd5f748d793ea1a29a0325cbfd2b/server/src/modules/pulls/latest-run.ts#L33) · [Isolation test](https://github.com/3anpaln/dev-digest/blob/c3a749db8ca0fd5f748d793ea1a29a0325cbfd2b/server/test/reviews.it.test.ts#L174)
- **2026-11-21** For usage accounting, keep missing token counts distinct from reported zeros. A successful Anthropic review can have no usage metadata. Keep the review result, warn about the missing metadata, and pass the original missing counts into cost calculation so the display fallback cannot create a zero-dollar charge. [Adapter test](test/anthropic-usage.test.ts#L12)
- **2026-11-21** When changing review cancellation, test it during final persistence as well as during a model call. An executor can pass its last cancellation check before the API updates the run. The conditional database transition decides which outcome wins, and the successful review writes share that transaction so cancellation can roll them back. [Executor](src/modules/reviews/run-executor.ts#L218) · [Race regression](test/reviews.it.test.ts#L299)
- **2026-11-21** Treat review log stream closure as a cue to refresh run history. The bus can close an accepted cancellation while the executor still has a provider request in flight. Test that the stream drains and closes before releasing that request, then check the persisted cancelled status and trace separately. [SSE bridge](src/modules/reviews/routes.ts#L66) · [Review integration tests](test/reviews.it.test.ts#L343)
- **2026-11-21** In Drizzle SQL templates, interpolate schema columns as identifiers and JSON keys as bound values. Cast a bound key to text when using the PostgreSQL JSON extraction operator so PostgreSQL selects object-key lookup. [PR run cost query](https://github.com/3anpaln/dev-digest/blob/1dee797ecf72b30db425f2298b47b78013be53bc/server/src/modules/pulls/latest-run.ts#L48)
- **2026-11-21** When diagnosing a conflicting-attempt cost warning, look up the trace by run ID and then compare entries for the logged attempt ID. Attempt IDs are local to a run, and a legitimate retry gets its own ID. Exact copies count once. Conflicting charges leave the total unknown because the trace cannot establish which charge is correct. [Cost aggregation test](test/run-cost.test.ts#L27)
- **2026-11-21** When assessing whether PR cost availability reveals review timing, check the run status in the same response first. Workspace callers already receive the latest run status, so delaying only the cost would leave the completion signal visible and add latency. [Latest run response](https://github.com/3anpaln/dev-digest/blob/1dee797ecf72b30db425f2298b47b78013be53bc/server/src/modules/pulls/latest-run.ts#L47)
- **2026-11-21** follow-up to “When a PR card appears cheaper than a multi-agent review”. The PR list now totals all review runs on the PR, and the trace drawer shows the selected run. Deduplicate attempts inside each run before adding run totals, since separate runs can reuse the same run-local attempt ID. Include a priced foreign-workspace run and a priced same-number PR in a second repository when testing the scope. [List aggregation](src/modules/pulls/latest-run.ts#L46) · [PostgreSQL test](test/reviews.it.test.ts#L185)
- **2026-11-21** When debugging a transient unknown PR total, distinguish a single-statement read snapshot from separate writes. A join reads run status and trace from the same snapshot, even when the application sums the returned rows later. Accepted cancellation writes the status before the executor can save its trace, so a snapshot taken in that interval can legitimately show a cancelled run with unknown cost. [Cost query](src/modules/pulls/latest-run.ts#L36) · [Run lifecycle](specs/review-runs.md?plain=1#L8)
- **2026-11-21** If the editor reports TS2550 for replaceAll in a server test, check which TypeScript project owns that file. The server config sets its library to ES2022 and includes only src. A global regular expression with replace is sufficient for fixed test-fixture substitutions. [TypeScript config](tsconfig.json#L20) · [Review fixture](test/reviews.it.test.ts#L327)
- **2026-11-21** follow-up to “If the editor reports TS2550”. Server tests now have their own no-emit TypeScript project, inheriting the runtime project aliases and library settings. For alias diagnostics in tests, run pnpm exec tsc -p test/tsconfig.json from server. Vitest resolves its aliases separately, so passing tests alone does not verify editor resolution. [Test project](test/tsconfig.json#L2) · [Vitest config](vitest.config.ts#L6)
- **2026-11-21** When a list response combines full counts with a short preview per record, compute the counts and row ranks in the same PostgreSQL subquery. Apply the per-record rank cap before selecting preview text so the server receives only the preview rows and counts still include findings beyond the cap. [Finding previews query](src/modules/pulls/finding-previews.ts#L10) · [Review integration test](test/reviews.it.test.ts#L130)
- **2026-11-21** follow-up to “When a list response combines full counts with a short preview per record”. Drizzle can emit subquery aliases unqualified in a join. Give count aliases names such as `suggestion_count` so they cannot collide with the joined table’s columns. Clone the full table schema with PostgreSQL’s `LIKE` when using a temporary table to verify a join. A reduced fixture can miss an ambiguous column that exists in the real schema. [Finding previews query](src/modules/pulls/finding-previews.ts#L25)
- **2026-11-25** When a saved trace returns 404 after cleanup, check which parent was deleted. Deleting the PR clears the run's PR link, and the run still establishes trace ownership. Deleting the run cascades to the trace, and PostgreSQL rejects a trace insert without a run. Preserve this distinction when changing the trace query. [PR foreign key](src/db/migrations/0000_init.sql#L361) · [Trace foreign key](src/db/migrations/0000_init.sql#L397) · [Lifecycle regression](test/reviews.it.test.ts#L300)
